## Context

Bounded project to bring the vault's four fishing notes (Bay Flats Lodge, Jurassic Lake Fishing, Southern Way Charters, Leader Formulas) plus the Troutbitten dry-fly clipping into a consistent structure, per a prior chat's advice about MOC/project splits, type taxonomies, and folder shallowness — validated against how this vault already does it elsewhere (`Clinical Reasoning MOC` vs. `Projects/Clinical Reasoning.md`, `Projects/_Todoist Link Convention.md` as the one-convention-per-topic model). The permanent hub is [[Fishing MOC]] (now filed in `Fishing/`); the rules live in [[_Fishing Notes Convention]]; this note is the bounded log and closes when the pass is done.

## Decisions

- `Fishing MOC.md` moved from vault root into `Fishing/`; the four content notes stay at vault root (folder depth buys nothing Dataview doesn't already give — same reasoning the vault already applies to Clippings).
- Type taxonomy: `destination`, `technique`, `source`, `reference`. `destination`/`technique` notes keep that type regardless of authorship; the `author` field (present vs. absent), not `type`, distinguishes self-authored from consulted material. Leader Formulas stays `type: technique` rather than being reclassified to `reference`.
- Frontmatter keys use underscores, not hyphens, going forward (`best_months`, `peak_months`, `water_temp`) — locked in now, before any note needed those fields.
- Removed three dangling wikilinks (`[[redfish]]`, `[[saltwater fly fishing]]`, `[[Louisiana fly fishing]]`) from Southern Way Charters — none resolved to real notes, and ad hoc topical links are redundant with `topic: fishing` + the MOC's Dataview queries.
- Vault was not under version control before this pass — `git init` + a baseline commit were done first so the whole pass is reversible.
- Normalization-flagging mechanism: a new fishing note only needs `topic: fishing` set to become visible to the system. The MOC's **Needs normalization** Dataview query surfaces anything missing `type`, or `type: destination` missing `best_months`, so half-finished notes stay visible without needing their own status field.
- `best_months`/`peak_months` schema: stored as `"MM-Mon"` strings (e.g. `"11-Nov"`) so plain alphabetical sort/GROUP BY in Dataview comes out in calendar order — no DataviewJS required. `best_months` = every month worth targeting (inclusive; list all twelve if genuinely good year-round); `peak_months` = the standout subset, only set when there's a real peak-vs-shoulder distinction (skipped on Jurassic Lake, since its whole season is strong for different reasons). This gives both a narrative "Best time to fish" section per note (with sources) and a queryable field, so "where can I fish in November" is answerable via a one-line Dataview query or the MOC's new "Where to fish, by month" tables.
- Crosslinking is now a standing part of normalizing any note (new or existing), not a one-time pass: added `## Related destinations` / `## Related techniques` sections with real wikilinks — [[Leader Formulas]] links out to all three destinations (which formula applies where) and to the Troutbitten clipping (shared George Harvey–style dry-fly leader concept); the destinations and the clipping link back. This is separate from the blanket `topic: fishing` discovery the MOC already gives every note — crosslinks are reserved for genuine relationships, not just shared topic.
- "Techniques database": the MOC's Techniques table now also counts inbound links (`length(file.inlinks)`) as a rough centrality signal, plus a **Technique concepts** table tracking named sub-techniques mentioned inside notes that don't have their own note yet (lagging curve, crash cast, hop mends, George Harvey dry-fly leader, grease the tippet — all from the Troutbitten clipping). Same rule as `Clinical Reasoning MOC`: promote a concept to its own note once 2+ sources reference it; let single-use mentions stay red.
